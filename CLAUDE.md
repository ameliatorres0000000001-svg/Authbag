# HENGZ AUTHENTIC — project rules for Claude Code
- Never make the system (code, rules or AI) issue a certificate on its own. Expert outcomes are the four in `src/shared/types.ts`. The only automated verdict is the AI verdict below.
- Only exception (approved by the owner): a HENGZ AUTHENTIC expert certificate, issued BY HAND by a named staff expert, only for a verification request the experts answered `consistent_with_references` (DB triggers in `0018_hengz_certificates.sql` enforce it). Wording: "Verified by HENGZ AUTHENTIC expert — consistent with HENGZ AUTHENTIC references"; guarantee valid only for buy-back by HENGZ AUTHENTIC. Numbered, QR-checkable, immutable, revocable; revoked automatically if the expert answer changes. Never let AI or automation issue one.
- Never let draft rules or `ai_suggested` observations affect outcomes. Never weaken DB triggers/CHECKs in migrations.
- AI pre-check (approved by the owner, 2026-11): while `expert_review_enabled` = 0 customers see the AI's comparison with reference photos of the EXACT identified model only (never another model; no reference → brand standards). The AI also recognises brand/model from a photo (identification only).
- AI verdict (owner decision, 2026-11-13): the AI scores each checkpoint 0–100; the verdict authentic / counterfeit / unidentified is computed in code (`src/shared/aiVerdict.ts`: weights, ≥90 and no clear deviation → authentic; confident deviation → counterfeit; unclear/missing key photo → unidentified) and shown to customers labelled as an AI score from photos. It is never an expert outcome and never stored as one (see the AI certificate sheet rule for how it may be presented). AI free text stays filtered (`src/shared/aiReview.ts`, English and Khmer); verdict labels come from `i18n.tsx`.
- AI certificate sheet (owner decision, 2026-11-16, replaces the earlier "never a certificate" rule for the AI result only): the AI result may be laid out and worded as the "Anajak Bag" AI certificate (`src/web/AiReport.tsx`, `src/web/reportPng.ts`), two pages like the owner's `certificate-ai.html`: cover (bag photo, brand, model, AI score, statement, notice, "Anajak Bag AI" signature line) then analysis by part. It is an AI probability from photos, never a guarantee: the notice stays on the sheet, "VERIFIED BY ANAJAK BAG AI" appears only for an `authentic` AI verdict (other verdicts say "Analysed by" and the matching statement). It shows only the customer's own bag photo (never a reference photo), uses its own `AIC-` number (never the HENGZ expert certificate numbering or wording), has no QR/seal/guarantee, is drawn in the browser and never stored, and is still never an expert outcome or a HENGZ expert certificate.
- Paint colour history (owner request, 2026-11-15): scanned colours are kept on the person's own phone only (`src/web/paintHistory.ts`, localStorage), because the paint page is open without login. No server copy.
- Never ask for, print or store secrets; use `wrangler secret put` / `wrangler login`.
- No demo/fake data. Empty states say "no data".
- UI strings go in `src/web/i18n.tsx` (km + en). Design tokens: `tailwind.config.js` (Haute Verification); references in `design-reference/stitch`.
- Commands: `npm test` (engine), `npm run typecheck`, `npm run build`, `npx wrangler dev`.
- Reference-photo guides (owner prompt, 2026-11-13, `GUIDE_SYSTEM_PROMPT` in `src/worker/vision.ts`): per box `popup_text` / `where_to_look` / `original_trait` / `fake_red_flag`, versioned (`GUIDE_VERSION`). They teach about the original reference model and common copy mistakes; they never judge a customer's bag. Counterfeit-labelled photos are never explained. Old guides are rewritten by the refresh job (Admin button + cron).
- Strap paint (owner request, 2026-11-17): the paint screen has a Body / Strap switch; the strap panel (`src/web/StrapPanel.tsx`) lists only published recipes staff tagged strap_safe / fast_soak (migration 0040, Admin checkboxes), shows tags and no percentages, no stock status, a custom colour gets a recipe only within ΔE 6, softener share is the owner guideline (20%).
- Home background (owner request, 2026-11-16): `Galaxy` has scenes galaxy / obsidian / aurora / marble / silk (pictures in `src/web/public/galaxy/`); the choice is kept on the person's phone only (`src/web/homeTheme.ts`, localStorage `hz_bg`), default obsidian (since 2026-11-22). Motion is transform-only and stops on lite phones / reduced motion.
- Home layout (owner request, 2026-11-16): classic or "bento" (big scan tile + small tiles, best sellers as a sideways row), chosen in the palette popover, kept on the phone only (`useHomeLayout`, localStorage `hz_layout`), default classic.
- App colours and background (owner request, 2026-11-17): dark theme is plum-black with champagne gold (CSS variables in `index.css`); every screen shares the Home scene picture under a dark veil via `--bg-pic` on `body` (`applyScenePic` in `homeTheme.ts`). The Scan pill/tile on Home goes to `/check` (not `/verify`, which is History). Best sellers are one swipeable top-5 row with a small date-code link under it.
- LINE interpreter (owner request, 2026-11-23): staff talk with customers / partners (Thai, Malay, Indonesian …) through the shop's LINE Official Account, in the app's Admin → "Customer chat" (`src/web/LineInbox.tsx`, `/api/line/*` in `src/worker/index.ts`, `src/worker/line.ts`, migration 0041, secrets `LINE_MESSAGING_SECRET` / `LINE_MESSAGING_TOKEN`). The AI only translates: customer text or voice (voice needs Gemini) → Khmer; staff write Khmer, read the translation, then send. The AI never replies by itself and never says a bag is authentic. Messages are deleted after 30 days; the webhook checks the LINE signature. WhatsApp (owner request, 2026-11-23, most partners use it) uses the same inbox through the WhatsApp Business Cloud API (`src/worker/whatsapp.ts`, `/api/whatsapp/webhook`, contacts stored as `wa:<number>`, secrets `WHATSAPP_TOKEN` / `WHATSAPP_PHONE_NUMBER_ID` / `WHATSAPP_APP_SECRET` / `WHATSAPP_VERIFY_TOKEN`); free text can be sent only within 24 hours of the customer's last message, and the phone number is never written to the audit log.
- Minimal black theme (owner request, 2026-11-22, replaces the plum-black / champagne-gold look and the shared Home picture behind every screen): dark theme is near-black neutrals with hairlines, a soft-white accent (the `gold` token), flat cards (no gradients, glow or blur) and Manrope headings; the light theme keeps paper white with the old gold accent. Every screen has a flat background; only Home still shows the chosen scene, default `obsidian`.
