# HENGZ AUTHENTIC — project rules for Claude Code
- Never make the system (code, rules or AI) issue a certificate on its own. Expert outcomes are the four in `src/shared/types.ts`. The only automated verdict is the AI verdict below.
- Only exception (approved by the owner): a HENGZ AUTHENTIC expert certificate, issued BY HAND by a named staff expert, only for a verification request the experts answered `consistent_with_references` (DB triggers in `0018_hengz_certificates.sql` enforce it). Wording: "Verified by HENGZ AUTHENTIC expert — consistent with HENGZ AUTHENTIC references"; guarantee valid only for buy-back by HENGZ AUTHENTIC. Numbered, QR-checkable, immutable, revocable; revoked automatically if the expert answer changes. Never let AI or automation issue one.
- Never let draft rules or `ai_suggested` observations affect outcomes. Never weaken DB triggers/CHECKs in migrations.
- AI pre-check (approved by the owner, 2026-11): while `expert_review_enabled` = 0 customers see the AI's comparison with reference photos of the EXACT identified model only (never another model; no reference → brand standards). The AI also recognises brand/model from a photo (identification only).
- AI verdict (owner decision, 2026-11-13): the AI scores each checkpoint 0–100; the verdict authentic / counterfeit / unidentified is computed in code (`src/shared/aiVerdict.ts`: weights, ≥90 and no clear deviation → authentic; confident deviation → counterfeit; unclear/missing key photo → unidentified) and shown to customers labelled as an AI score from photos. It is never a certificate, never an expert outcome, never stored as one. AI free text stays filtered (`src/shared/aiReview.ts`, English and Khmer); verdict labels come from `i18n.tsx`.
- Never ask for, print or store secrets; use `wrangler secret put` / `wrangler login`.
- No demo/fake data. Empty states say "no data".
- UI strings go in `src/web/i18n.tsx` (km + en). Design tokens: `tailwind.config.js` (Haute Verification); references in `design-reference/stitch`.
- Commands: `npm test` (engine), `npm run typecheck`, `npm run build`, `npx wrangler dev`.
- Reference-photo guides (owner prompt, 2026-11-13, `GUIDE_SYSTEM_PROMPT` in `src/worker/vision.ts`): per box `popup_text` / `where_to_look` / `original_trait` / `fake_red_flag`, versioned (`GUIDE_VERSION`). They teach about the original reference model and common copy mistakes; they never judge a customer's bag. Counterfeit-labelled photos are never explained. Old guides are rewritten by the refresh job (Admin button + cron).
